# Spec 107 — Plan

## Shape

The package mirrors Specs 104 and 106: spec.md states
the study; claims.md and aee-claims.json carry the six
claims in the program's claim form; the cycle-1 ranking
record and the I-1 / M-1 registrations are filed at
registration (records/cycle-1-registration-2026-11-26.md),
because the loop's discipline is that registration
precedes execution; E-1 is registered by reference to
Spec 101's package, whose own registration and binding
floor record govern it. The history ledger opens live at
registration.

## Venues and discipline

Registration lands from the VM by the GitHub API
(no clone; the execution-risk flag binds VM clones).
Execution runs on tower-compute in a fresh clone under
`~/.syncyard/worktrees/glossa/`, on the study branch;
custody bytes (donor B, simulation intermediates) live
under `glossa-custody/spec107/` and are never committed.
Every pull request merges only on genuine per-job CI
green (10/10); the known Spec 095 T404 timing flake's
reruns are disclosed where they occur; branches are
deleted in the same motion as their merges.

## Risks named in advance

- I-1's Latin donor preparation (classical normalization)
  is a judgment; it is fixed in the registration so the
  run cannot tune it, and the Meroitic donor carries no
  such preparation.
- M-1's validations may fail (a join or partition
  mismatch); the registered response is STOP and file,
  not repair-in-flight.
- E-1's intake transcription is the accuracy-critical
  step; the identity record states its conventions and
  its census beside the chapter's stated figure, and the
  scoring is mechanical over the intaken state, run
  twice with an independent recount.
