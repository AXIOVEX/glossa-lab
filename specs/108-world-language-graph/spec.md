## 1. What this spec is

This spec builds and populates the World Language
Graph specified by the design: a versioned, source-bound
assertion system with a graph-shaped canonical store,
in which languages and scripts are distinct node kinds
joined only by time-scoped WRITES relations; placements
exist only as sourced placement assertions and
hypothesis edges, never as node facts; geometry is
typed before any coordinate exists; a gap register is
generated mechanically for every open case; and the
whole system is evidence infrastructure for the
ELSEWHERE baselines, not a fourth baseline.

**The graph moves nothing.** No Spec 106 baseline,
template, or pin is amended by this work; no program
standing, verdict, or tally changes. Content reaches a
baseline only through a reviewed axiom candidate pack
and a versioned baseline amendment, which are program
review acts outside this commission. The three existing
baseline pins are recorded in the release record
untouched: Indus `eb0e1d62…`, Eteocypriot `fca1cc8a…`,
Meroitic (version 2) `ecabd227…`.

## 2. The build (design §§1–3, 7)

The canonical store is the set of append-only,
text-diffable streams of design §"Architecture at a
glance", held in this package at `graph/`:

- `sources.jsonl` — one record per source actually
  opened, with bibliographic identity, version, access
  route, licence or access constraint, and date opened.
- `nodes.jsonl` — language and script nodes. A node
  carries identity and links to assertions; it has **no
  unqualified family field** (the placement rule,
  design §5.7, enforced architecturally).
- `edges.jsonl` — relationship assertions. The seven
  historical predicates (GENETIC_DESCENT,
  CONTACT_BORROWING with mandatory feature scope,
  SCRIPT_DESCENT, SCRIPT_BORROWING, AREAL_CONVERGENCE,
  POPULATION_MOVEMENT confined to population entities,
  PROPOSED_RELATION) are mechanically distinct;
  structural relations (WRITES, ATTESTED_AT,
  ADMINISTERED_BY / USED_IN_POLITY) are stored apart
  from the historical layer. Competing edges coexist;
  there is no merge-to-consensus operation. Transitive
  closure is computed only within admitted
  GENETIC_DESCENT.
- `assertions.jsonl` — field-level sourced assertions,
  each with exactly one evidence class (F/K/H), a
  confidence label, source references with locators, a
  source grade (P1–P4), a review state, and a removal
  condition. UNSOURCED appears only as an (H) variable.
- `gaps.jsonl` — gap-register entries generated by the
  rule of design §4.2.
- `releases.jsonl` — immutable graph releases with
  record counts, stream hashes, the source-manifest
  hash, the schema version, and the audit outputs that
  admitted the release.
- `baseline-links.jsonl` — mappings from graph
  assertions to baseline axioms that have adopted them.
  At this release it carries the identity mappings for
  the three priority programs' already-adopted
  assertions only where the filed record names them;
  it creates no adoption.

Status scales are the design's: script S0–S4, language
L0–L5, carried as dated sourced assessment assertions;
a script's status never transfers to its language.

Geometry follows design §3: geometry assertions are
typed (ATTESTED_FINDSPOT_SET, ATTESTED_DISTRIBUTION,
DISPLAY_CENTROID, INFERRED_HOMELAND,
RECONSTRUCTED_STAGE_AREA, CONTACT_ZONE, NO_GEOMETRY)
before any coordinate exists; inferred geometry is
structurally distinct in storage, rendering, and
export; NO_GEOMETRY nodes live in a first-class
off-sphere index; time is an interval query with no
interpolation. The eight never-imply rules of design
§3.8 are binding acceptance criteria (TC-108-07).
This build implements the geometry typing, the view
state, and a reproducible spherical-projection view
record; it does not choose a globe library, per the
design.

The implementation lives at `tools/` in this package:
the schema and store, the population builder, the
gap-register generator, the projection/view generator,
and the audit suite implementing WLG-01..09
(design §5.5). Every job in this study emits periodic
timestamped progress indicators with countable work
done against work total (the owner's fleet-wide
constraint of 2026-11-26).

## 3. Population (design §6)

Population proceeds in the design's batches:

- **B0** Authorities and crosswalks: the classification
  authority in force is pinned and recorded (Glottolog;
  the version actually reachable and used is the
  version recorded — no version is claimed that was not
  opened), identifier crosswalks are built, and the
  source registry is founded, including the research
  report as the first ingestion source with its access
  and provenance terms on its record.
- **B1** Global skeleton: language and script nodes at
  SKELETON depth for the census the sources support.
  Anything not verified is NOT_ENUMERATED or UNKNOWN,
  never guessed.
- **B2** Decipherment histories: for every deciphered,
  partly deciphered, or claimed-deciphered script in
  the ingestion source, the mechanism, the independent
  verification, and the current status assessment.
  Failed and unsustained claims are recorded as claims
  with their standing, not as decipherments.
- **B3** Family, contact, and script-history edges,
  with competing school proposals as separate
  PROPOSED_RELATION edges.
- **B4** Movement and covariates: population-movement
  assertions confined to population entities, from the
  ancient-DNA and archaeological material in the
  ingestion source, carrying the genes-are-not-language
  restriction on their face; covariate blocks populated
  or carrying the explicit NO_ASSERTION_POPULATED
  state.
- **B5** Gap census completion: every gap entry
  reviewed against design §4.3 (known, missing,
  blockers, candidates with evidence bands A–D,
  movement conditions, priority). Within-band order is
  a work order, not a likelihood. CLOSED_INDETERMINATE
  is a substantive lifecycle state.
- **B6** Priority reconciliation: the three programs'
  nodes, edges, and gaps reconciled line by line
  against the filed program record (Specs 096–107 and
  the Spec 106 baselines), which **governs** wherever
  the research report and the filed record differ. The
  three programs stand at DOSSIER depth. On the filed
  record: the Indus anchor register stands 287 anchors
  with a 94 strict core at 3 E + 66 I + 4 R + 3 P +
  18 U, exactly 1 of 94 (M047) independently sourced;
  the Meroitic script (S3) and language (L2) are kept
  unmerged; the Spec 102 affiliation gates G-1 and G-2
  are carried unchanged; the Eteocypriot pilot's
  prediction leg never met its 100-sign unseen-text
  floor and Spec 101's registered outcome (C101-1 NOT
  SUPPORTED, enrichment target) is recorded as the
  program record states it.

Every batch passes the design's seven-step verification
gate (§6.7) before its items enter a release: extraction
with locators; an independent source check; a type
discipline check; a competition sweep; independent
duplicate extraction for high-impact items; the
mechanical audits WLG-01..09; and a filed batch report
(attempted, landed, quarantined, with reasons).
Custody and licensing terms are recorded on the source
records; restricted bytes are never committed — no
Holdat corpus bytes, no CISI material, no Otten corpus
bytes, no Rilly & de Voogt lexicon text. The graph
stores sourced assertions and references, not
restricted content.

## 4. Acceptance (design §§5.5, 7)

The build is accepted only when: audits WLG-01..09 run
and pass on the populated release; a view reproduces
from its view state; the off-sphere index is complete
for the release; the competing-placement case
(Meroitic) is present as competing assertions; the
no-standing-moves audit over this study's own landings
is clean; and the release record files the three
distinct hashes (graph snapshot, source manifest, and
the untouched baseline pins).

## 5. What this spec does not do

It does not amend any baseline, spawn any ELSEWHERE
instance, adjudicate any placement, run any decipherment
test, or move any standing. It does not present any
placement estimate as a fact anywhere, including in its
own reports. Papers, if any ever draw on the graph,
carry no internal language (the owner's directive of
2026-11-27); this build produces repo records and data,
not a paper.
